# 04 · 验证记录

> 记录哪些路走通了、哪些被证伪，以及每条结论对应的实车现象。
>
> 验证环境：长安启源 C589 PHEV，启源 OS（Android 9 / API 28），2026-08。

---

## 1. 认证绕过验证（路线一）

### 1.1 目标

确认"工程模式二级认证"是否可以被本地假服务端绕过，以及绕过之后车机是否真的
允许切换 USB 模式。

### 1.2 环境

| 项目 | 值 |
|---|---|
| 热点 | Windows 移动热点，网关 `192.168.137.1` |
| 车机 IP | `192.168.137.x`（由热点分配） |
| 域名 | `spm.auto-pai.com` |
| 证书 | 自签，CN 同名 |
| 证书校验 | 车机 App 不校验（任意证书可通过） |

### 1.3 过程

1. 笔记本写入 hosts 或启动迷你 DNS，把目标域名指向 `192.168.137.1`；
2. 启动自签 HTTPS 服务，三个接口返回 `{"code":"0000"}`；
3. 车机连接热点，进入工程模式；
4. 输入任意手机号 + 任意验证码，点登录；
5. 观察笔记本日志与车机界面。

### 1.4 结果

| 观察点 | 结果 |
|---|---|
| 车机请求是否到达笔记本 | ✅ 日志出现 `POST /tlc/auth/v1/login` |
| 证书校验 | ✅ 自签证书直接通过 |
| 响应 `code=0000` | ✅ 车机显示登录成功 |
| 登录后能否点"切换为 ADB 模式" | ✅ 可以 |
| 切换后 `adb devices` | ✅ 可见设备 |
| 证书/域名是否需要匹配 | ❌ 不需要 |

结论：

> 二级认证的信任边界完全依赖"域名解析到真实服务器"。
> 域名被指向本地后，证书与响应都可以伪造，认证即可通过。

### 1.5 边界

- 该流程只影响认证 UI，不向车机下发任何内容；
- 车机侧仍会执行自己的 USB 切换逻辑，工具不直接碰车机；
- 不同 OTA 版本如果改为校验证书或校验响应签名，此方法会失效。

## 2. 失败路径（已证伪）

### 2.1 直接写 `sys.usb.config`

```bash
# 仅说明为什么不行，不要在生产环境尝试
setprop sys.usb.config mass_storage,adb
```

结果：SELinux 拒绝，普通应用与 adb shell 都没有该系统属性的写权限。

### 2.2 借道 MTK EngineerMode 的 emsvr

- `ShellExe.execCommandOnServer` 会向 LocalSocket 发送
  `FUNCTION_EM_SHELL_CMD_EXECUTION=80001`；
- 本车**没有** `/dev/socket/EngineerModeServer`；
- 该应用运行在 radio uid 域，普通应用无法连入。

结论：死路。

### 2.3 HIDL `IEmd.setUsbPort()`

- 属于 `vendor.mediatek.hardware.engineermode`；
- untrusted_app 无 HIDL 访问权；
- 且它控制 UART/USB 端口切换，不是 ADB 开关本身。

结论：不可行。

### 2.4 无障碍自动化点击

```
拉起 TSP Factory MainActivity
  → 输入 6 位 PIN
  → 进入 USB 切换
  → 点击"切换为 ADB 模式"
```

结果：**失败**。切换前出现"安全开启工程模式"的车端认证，绑定手机号，
认证不通过就不执行切换。自动化只能过 PIN，过不了第二道门。

结论：UI 自动化不可行；要过第二道门只能冒充服务端（路线一）。

### 2.5 `Settings.Global` 写法

```java
Settings.Global.putInt(cr, "adb_enabled", 1);
Settings.Global.putInt(cr, "usb_mass_storage_enabled", 1);
```

- 写入成功、无异常；
- 但 `sys.usb.config` 不变，`adb devices` 不恢复，PC 端不出现 U 盘；
- 原因：该链路由 MCU 属性控制，`Settings.Global` 的键在这条路径上没有监听者。

结论：对"开发者选项里的 ADB 开关"有效，对"USB 口 host/device 角色切换"无效。

## 3. 成功路径

### 3.1 工程模式内切换

通过路线一完成认证后，点"切换为 ADB 模式 / U 盘模式"：

| 操作 | 现象 |
|---|---|
| 切 U 盘模式（值 2） | PC 端出现 U 盘；`adb devices` 断开 |
| 切 ADB 模式（值 1） | U 盘消失；`adb devices` 恢复 |
| 重复切换 | 稳定，未见需要重启 |

### 3.2 APK 直接写属性（路线二）

ADB 已开启后安装自研 APK，由 APK 调用 CarService 写同一个属性：

| 前提 | 结果 |
|---|---|
| 能通过 CarService 入口校验 | ✅ 可拿到 `mcu` 管理器 |
| 写 `557921325` 值为 1 / 2 | ✅ 与工程模式效果一致 |
| 车机重启后 | ✅ 应用仍可切换（不需要再走工程模式） |

前提细节见 [02-进阶-APK直接切换.md](02-进阶-APK直接切换.md)。

## 4. 汇总

| 路径 | 机制成立 | 本车可用 | 结论 |
|---|---|---|---|
| 本地假认证服务端 | ✅ | ✅ | 路线一，用于首次开启 |
| `sys.usb.config` | ✅ | ❌ | 权限不足 |
| emsvr LocalSocket | ❌ | ❌ | socket 不存在 |
| HIDL `IEmd` | ✅ | ❌ | 无访问权 |
| 无障碍自动化 | ✅ | ❌ | 二级认证拦截 |
| `Settings.Global.adb_enabled` | ✅ | ⚠️ | 只对开发者选项有效 |
| MCU 属性 `557921325` | ✅ | ✅ | 工程模式与 APK 共用 |
| 远程 ADB（T-Box 作业） | ✅ | ❌ | 车厂云端链路，app 侧不可用 |

本仓库不附带原始日志、截图和反编译产物：

- 日志含 VIN、手机号、设备标识；
- 反编译产物属于第三方版权内容；
- 部分截图能看到 VIN / 手机号。

结论以"现象 + 判定"记录。如果你要复现，请在自己的车上用只读命令观察，
不要把原始日志上传到公开仓库。
