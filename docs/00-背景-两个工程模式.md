# 00 · 背景：两个"工程模式"

> 这一篇只解释背景：车机上的"工程模式"到底是哪个应用、它怎么拦你、
> USB 切换最后写到了哪里。具体怎么做见 [01](01-首次开启-工程模式与认证.md) 和
> [02](02-进阶-APK直接切换.md)。

---

## 1. 两个同名的"工程模式"

| | MTK EngineerMode | 长安 TSP Factory |
|---|---|---|
| 包名 | `com.mediatek.engineermode` | `com.chinatsp.tfactoryapp` |
| 来源 | 联发科平台自带 | 长安自研 |
| 入口 | 拨号暗码 / 特定 Activity | 设置隐藏入口 / 广播 |
| 菜单 | Hardware Testing、USB、ATCI | LOG、USB 切换、车型配置、TBox、写 VIN、OTA 工程模式等 16 项 |
| ADB 相关实现 | 写 `sys.usb.config` | 写 MCU 属性，走 CarService |

本车实际使用的是 **TSP Factory**。MTK 的 EngineerMode 即使存在，USB 菜单在量产
user 版里也会被移除，所以不要照着 MTK 的代码找入口。

---

## 2. TSP Factory 的两道门

### 2.1 第一道：6 位 PIN

- 打开 `MainActivity`（exported）后先进入 6 位数字键盘；
- 输入值与资源里的 MD5 校验值比对；
- 只是界面门，不参与后续属性写入。

PIN 的具体值不在本仓库公开。

### 2.2 第二道：二级认证

- 点"切换为 ADB 模式 / U 盘模式"时，要求"安全开启工程模式"的车端认证；
- 认证绑定手机号，走云端接口；
- **只挡 UI 操作，不挡底层属性写入**。

这解释了一个常见困惑：为什么自动化点击走不通，但直接写属性却可以。
自动化走 UI，必须过第二道门；直接写属性绕开 UI，只面对 CarService 的入口校验。

## 3. USB 切换的真实落点

```
UsbFragment
  → CarMcuManagerUtil.setMcuModeSelect(mode)
    → CarMcuManager.ID_MCU_USB_MODE_SELECT = 557921325  (0x2141342D, vendor 段)
      → CarService → VHAL → MCU
```

| 值 | 含义 |
|---|---|
| 1 | ADB 模式 |
| 2 | U 盘模式 |

切换的本质不是改 Android 的 USB 配置字符串，而是让 **MCU 物理切换 USB 口的
host/device 角色**。因此：

1. 切到 U 盘模式后 `adb devices` 会消失；
2. `sys.usb.config` / `Settings.Global.adb_enabled` 不会改变这个状态——链路上没有监听者。

### 3.1 与常见 Android 机制的区别

| 机制 | 写入目标 | 监听者 | 本车是否有效 |
|---|---|---|---|
| 开发者选项 USB 调试 | `Settings.Global.adb_enabled` | `system_server` UsbDeviceManager | 对"ADB 功能开关"有效，对 MCU 角色无效 |
| MTK EngineerMode | `sys.usb.config` | init / USB HAL | 需 radio/platform 域权限，普通应用不可写 |
| TSP Factory | MCU 属性 `557921325` | CarService → VHAL → MCU | 有效 |

## 4. 为什么不能照抄 MTK 的代码

| 写法 | 失败原因 |
|---|---|
| `SystemProperties.set("sys.usb.config", ...)` | SELinux 拦截，普通应用无 `set_prop` 权限 |
| `ShellExe` → emsvr LocalSocket | 本车没有 `/dev/socket/EngineerModeServer`，且 EM 以 radio uid 运行 |
| HIDL `IEmd.setUsbPort()` | untrusted_app 无 HIDL 访问权 |

根本原因：

> **权限跟着进程域（签名 + 安装位置 + SELinux 域）走，不跟代码走。**
> 把系统应用的代码复制到普通应用里，代码能编译，权限不会跟过来。

## 5. 由此得到的两条路线

| 路线 | 解决什么 | 前提 | 文档 |
|---|---|---|---|
| 一：工程模式 + 认证绕过 | 第一次打开 ADB | 能连热点、能改笔记本 hosts | [01](01-首次开启-工程模式与认证.md) |
| 二：APK 直接写属性 | 以后不再走工程模式 | ADB 已开、APK 能过 CarService 入口校验 | [02](02-进阶-APK直接切换.md) |

路线一利用"二级认证只挡 UI"，让车机自己完成切换；
路线二利用"CarService 入口只看进程名"，让应用直接写同一个属性。
