# 03 · 风险与恢复

> 这一页比前两页更重要。切换 USB 模式最坏的结果是 **ADB 断开、U 盘也认不到**，
> 而你正需要 ADB 去修它。动手前先把恢复路径准备好。

---

## 1. 风险分级

| 操作 | 风险 | 可能后果 | 可恢复性 |
|---|---|---|---|
| 只读 `dumpsys` / `getprop` | 🟢 低 | 无 | — |
| 写 `Settings.Global.adb_enabled` | 🟢 低 | 开发者选项的 ADB 开关变化 | 再写回即可 |
| 写 `Settings.Global.usb_mass_storage_enabled` | 🟡 中 | 部分配置下 USB 行为变化 | 写回 0 |
| 写 MCU 属性 `557921325` | 🟠 中高 | USB 口角色切换，ADB 可能断开 | 需要另一条路径切回 |
| 伪造进程名进入 CarService | 🟠 中高 | 可写 vendor 属性，误写可能影响车辆功能 | 取决于写入了什么 |
| 修改电源/驱动/制动相关属性 | 🔴 高 | 车辆异常、安全风险 | **不要做** |

---

## 2. 切到 U 盘模式后，怎么恢复 ADB

这是最容易翻车的场景。按可靠性从高到低：

### 2.1 用车机工程模式 UI 切回（最可靠）

1. 打开 TSP Factory 工程模式；
2. 输入 PIN（你自己的车，自行保管）；
3. 进入"USB 切换"；
4. 点"切换为 ADB 模式"。

前提：你能通过二级认证（绑定手机号）。如果认证失败，看下一条。

### 2.2 用已安装的切换工具切回

如果你之前已经装了一个能在车机上运行、并能写 `557921325` 的应用：

- 先确认它仍在运行（切 U 盘不会卸载应用）；
- 在车机桌面上打开它，点"切换为 ADB 模式"。

前提：该应用本身能通过 CarService 入口校验。**不要在没有这个前提时先把 USB 切走。**

### 2.3 重启车机

部分配置下 MCU 会在重新上电时回到默认 USB 角色（通常是 ADB/device）。
但这不是保证——有些固件会记忆上次选择。

### 2.4 恢复出厂设置

会清除用户数据与应用，但通常能恢复默认 USB 配置。
执行前确认你不需要车机里的数据。

### 2.5 联系 4S 店 / 售后

如果以上都不行，且车机无法再被 ADB 识别，这是最后的兜底。

## 3. 最小风险做法

如果你只是想临时用 ADB：

1. **先确认车机原本就是 ADB 模式**（`adb devices` 能看到设备）；
2. 不要为了"试试"切成 U 盘模式；
3. 如果必须切换，先准备好 2.1 或 2.2 的恢复路径；
4. 切换后立刻验证能否切回，再继续其他操作；
5. 全程记录你写了哪个属性、写了什么值。

---

## 4. 权限风险

### 4.1 `WRITE_SECURE_SETTINGS`

- 可以通过 `pm grant` 授予（取决于车机策略）；
- 拿到后能改大量系统设置，误改可能影响车机行为；
- 只在你自己的应用里使用，不要做成"一键优化"分享给别人。

### 4.2 CarService 入口

- 通过入口校验后，能拿到的不仅是 USB 模式属性；
- `mcu` / `property` 下还有电源、驱动、灯光等属性；
- **能写不等于该写**。本仓库不建议对任何车辆功能属性做批量写入。

---

## 5. 保修、安全与法律

- 修改系统设置、伪造进程名、写入厂商属性，可能被厂商视为非授权修改，
  从而影响保修；
- 切到 U 盘模式后 ADB 断开，可能影响后续诊断与 OTA；
- 不要把本仓库的方法用于他人车辆；
- 不同地区的法律对车辆改装/诊断有不同要求，请自行确认。

---

## 6. 不要做的事

- ❌ 不要在公共停车场、租车、他人车辆上尝试；
- ❌ 不要写电源、驱动、制动、转向相关属性；
- ❌ 不要把 PIN、口令、白名单进程名、签名私钥提交到任何公开仓库；
- ❌ 不要打包"一键开 ADB"的 APK 分发给不确定风险的人；
- ❌ 不要在切换 USB 模式的同时进行 OTA。

---

## 7. 出了问题怎么求助

在仓库 Issue 中提供：

- 车型 / 年款 / OTA 版本；
- 你执行了哪一步（不要贴 PIN、口令、VIN）；
- `adb devices` 是否还能看到设备；
- 车机屏幕上的提示。

不要上传完整 `dumpsys`、`logcat` 或截图原图——里面可能有 VIN、位置和账号信息。
